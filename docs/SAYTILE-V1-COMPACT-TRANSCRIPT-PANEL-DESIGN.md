# Saytile V1｜紧凑型文字优先常驻输入板：目标设计

> 状态：用户确认的目标设计（2026-11-07）
> 适用范围：V1 macOS 原生输入板与常驻状态入口
> 工程基线：PR #6 `engine/single-transcript-integrated-20261107`
> 本文是产品与视觉交互验收规范，不代表界面已实现或生产 RC 已替换。

## 1. 设计目标

Saytile 是始终待命的个人语音输入与表达工作台。主界面不是录音控制器，也不是 AI 状态仪表盘，而是一块持续呈现用户表达的紧凑文字空间。

最高优先级：
1. 用户说出的文字是面板主体，第一行就应该是文字，不先展示产品名称、标题、巨大状态栏或波形。
2. 控制和状态退居次要层级，轻量、安静、可预测，不打断表达。
3. 用户能一眼判断是否正在收音，以及当前是否正在识别/修正；不需要理解内部模型与专家工作流。
4. 收起面板不停止收音；阅读、选字或编辑旧内容时，新文本不得抢焦点或强制滚动。
5. 保留 V1 已有的原音持久化、历史档案、编辑、搜索、回听、复制、明确目标插入与故障恢复能力。

## 2. 面板形态与尺寸

采用紧凑的圆角矩形浮动面板，不采用长条工具栏，不采用传统录音器的大型波形视觉。

27 英寸显示器设计基准：
- 目标宽度：320–360 pt，约占 2560 pt 逻辑宽度的 1/8。
- 常态高度：约 200–260 pt；内容少时自然收紧，不为装饰元素保留空白。
- 内容增长时在固定范围内滚动，最大高度建议不超过 480 pt（约屏幕高度一半）。
- 面板宽高和位置应在多显示器、不同缩放比例与可用屏幕区域下自适应；尺寸不是对物理像素的硬编码。
- 不能因持续录音、ASR 中间结果或文字段落增加而无限增高。

## 3. 信息架构：文字优先

### 顶部状态行（紧凑）

- 不显示大号 Saytile 产品名称。主面板可完全省略字标；品牌只由菜单栏图标、App 图标和设置/档案承载。
- 顶部仅保留一个低对比度状态标识（小圆点/短波形 + 短标签）及一个小型更多菜单入口。
- 顶部状态行高度目标约 24–30 pt，不能形成独立的大标题栏。
- 状态标识不可只依赖颜色，必须有短文本或可访问性标签。

### 主文字区（绝对主体）

- 文字从面板顶部内容区的第一行开始；不得先放大 Logo、产品名、日期、标题、模式切换或大波形。
- 中文默认字号建议 15–17 pt，行距舒适；英文与中英混排需自然换行。
- 当前唯一 transcript 持续出现、持续修正；不显示多模型候选、版本选择、Raw/Formatted 或润色结果。
- 光标/末尾活动提示克制，不持续闪烁造成视觉噪声。
- 识别中间稿、稳定文字与 GPT 修正统一呈现为同一份忠实转写；不得因后台修正而跳动整块布局。
- 文字选择、复制和滚动行为优先于自动跟随；用户主动滚离底部后暂停自动滚动，并提供轻量“回到最新”入口。

### 底部轻操作区

- 不放大型波形。实时音量/活动提示最多使用一条很小的短波形或动态点阵，作为辅助状态，不得占据独立的大块高度。
- 常用辅助动作（例如复制）可用小图标放在底部一侧；不需要常驻的“复制/插入/设置/历史”整排大按钮。
- 历史、设置、直接输入目标绑定、档案管理等低频操作放入更多菜单或独立窗口。
- 保持现有“自由记录/直接输入”产品能力，但不要把模式切换做成主面板的永久大分段控件；目标绑定状态只在直接输入启用时用一条短提示表达。

## 4. 核心控制：一个整合式按钮

将开始/暂停/恢复整合为同一个状态切换按钮，不同时展示多个录音控制按钮。

- 未开启收音：按钮呈现开始/麦克风语义，点击后开启持续收音。
- 正在收音：同一按钮呈现暂停语义，点击后暂停采集。
- 已暂停：同一按钮呈现继续/播放语义，点击后恢复收音。
- 不额外增加一个常驻“停止/结束”按钮。停止/退出类低频动作如确有必要，放入更多菜单，并明确其与暂停、收起面板的区别。
- 按钮视觉尺寸保持克制，但实际鼠标命中区域必须足够大：建议 34–38 pt 方形命中区域，图形本身约 13–16 pt；不可用过小的 16–20 pt 图标热区。
- 按钮不应居中占据文字视线。优先放在面板右下角/底部边缘的安静位置，或与底部辅助动作同一基线；不得覆盖文字、光标或滚动区域。
- 点击区域与视觉图形可以分离：视觉轻、热区可靠；hover/focus/pressed 状态明确但不过度发光。
- 鼠标悬停、键盘辅助操作与 VoiceOver 必须有清楚的标签和状态反馈。

## 5. 状态模型：不再使用“待命”描述已开启但暂时无声

产品只向用户表达必要的收音状态与识别子状态，不展示模型内部细节。

### 收音主状态
1. **未开启**：麦克风尚未启动；显示“点击开始”或等价提示。
2. **聆听中**：收音已开启，持续等待用户讲话。即使当前没有声音，也仍然是“聆听中”，不是“待命”或“未开启”。
3. **已暂停**：用户明确暂停收音；文字与原音已保存内容继续保留。
4. **需要恢复**：权限、设备或持久化等问题导致收音中断；明确说明原因与可执行恢复操作。

### 聆听中的轻量活动子状态
- **等待讲话/当前无声**：收音仍在持续；仅显示低调的聆听标识，不显示“待命”。
- **检测到讲话/正在识别**：轻量活动点/短波形；文字开始出现。
- **正在修正**：仅在用户可感知的修正阶段短暂显示“正在修正”，不显示 GPT、ASR 专家、候选来源或模型名称。
- 无声与有声是聆听中的活动差异，不是两个需要用户操作的主状态。

状态必须由真实采集、识别和修正生命周期驱动，不可根据 UI 动画猜测。声音活动波形只反映真实音量/活动，不能被误解为识别准确率或模型进度。

## 6. 视觉语言

- 延续已探索的柔和紫/蓝方向，但避免通用 AI 仪表盘式的强紫色发光、过度渐变和大面积装饰波纹。
- 采用轻盈、安静、精致的半透明或柔和实体材质；优先保证文字对比度、清晰度和桌面环境下的可读性。
- 卡片边界、阴影和圆角克制，避免厚重悬浮感。
- 状态色仅作小面积辅助；错误状态可适度提高对比度。
- 不使用大面积音频波形、呼吸光圈、装饰性声浪、夸张动画。
- 动效只服务于状态转换和文字到达：短、柔和、低频；无声聆听时界面应几乎静止。

## 7. 常驻入口与小图标

- 菜单栏图标是默认常驻入口与全局状态指示，显示收音是否开启/暂停/异常。
- 菜单栏点击可展开主面板或简洁状态菜单；不应重复出现一个庞大的控制面板。
- 可选的极小桌面悬浮入口只作为菜单栏被隐藏/不可见时的替代入口，默认关闭或由用户主动开启。
- 小入口仅使用品牌语音符号，不重复写 Saytile；可显示极轻的状态点。点击后展开主文字板。
- 不默认同时显示菜单栏图标和桌面悬浮入口，避免双重常驻和视觉噪声。

## 8. 与现有 V1 产品契约的关系

本设计只改变界面层级、窗口尺寸与交互呈现，不得改变：
- 持续采集与独立原音保存；识别故障不能导致原音丢失。
- 用户只看到一份忠实文字；不润色、不扩写、不翻译、不展示多模型候选。
- 收起面板不等于停止收音。
- 暂停明确停止采集；恢复后继续正常工作。
- 用户编辑优先；后台识别不得覆盖用户编辑。
- 外部草稿插入须遵守精确范围所有权、目标变化保护和至多一次自动尝试；不自动发送、不按回车、不重放不确定操作。
- 历史档案、回听、搜索、复制、原音独立删除等能力继续存在。
- 不要求用户成为默认测试员；真实麦克风、外部目标应用和长时稳定性须由工程隔离验收。

## 9. 原生工程实现边界

当前工程已有 AppKit `NSPanel`、菜单栏 `NSStatusItem`、SwiftUI `InputPanelView`、`AppModel.toggleCapture()`、收音状态与转写模型。应优先重构现有输入板，不另起第二套音频/识别状态管理。

建议涉及：
- `Sources/SaytileApp/Views.swift`：重排输入板结构，文字前置，缩减状态与控制，收纳低频操作。
- `Sources/SaytileApp/SaytileApp.swift`：调整 NSPanel 默认尺寸、最小/最大尺寸、定位与收起行为；保留非激活面板和 Spaces 行为。
- `Sources/SaytileApp/Theme.swift`：统一轻量状态指示、按钮命中区域与视觉 token。
- `Sources/SaytileApp/AppModel.swift`：仅在必要时提供明确的 capture/recognition 子状态；不得重建音频状态机或改变引擎。

实施前核对 PR #6 最新 head；不要基于旧 SHA 覆盖后续并行修复。不得修改生产 main、RC1、用户数据库、私人音频、真实对话或密钥。

## 10. 验收标准

### 视觉与布局
- 320–360 pt 宽度下，首行即显示 transcript；不出现大 Logo/产品名/大标题/大波形。
- 常态约 200–260 pt 高；无内容时不留下装饰性空白；长文本不撑爆窗口。
- 唯一核心收音控制按钮视觉克制，实际点击热区至少 34 pt；不会误触或覆盖文字。
- 状态信息不与文字争夺层级；收音中无声仍明确显示“聆听中”。
- 多语言文本、长段落、错误提示、直接输入绑定提示均能自然适配。

### 状态与交互
- 未开启 → 聆听中 → 已暂停 → 聆听中，始终使用同一核心按钮。
- 聆听中无声与有声仅改变轻量活动提示，不改变主状态。
- 识别/修正状态可见但不持续闪烁、不改变面板整体尺寸。
- 收起面板后采集继续；菜单栏状态准确。
- 阅读旧文字、选择文字、编辑文字时不抢焦点、不强制滚动。
- VoiceOver、键盘可达性、鼠标 hover/focus/pressed 状态完整。

### 回归与交付
- 现有原生测试、AppModel 测试、UI 契约和 CI 全部通过。
- 对新尺寸、窗口最小/最大约束、点击热区、状态转换、滚动跟随与多显示器定位增加针对性测试。
- 不以 CI 通过替代真实麦克风、外部应用插入、睡眠唤醒和长时稳定性验收。
- 本文是目标设计；实现完成前不得宣称已实装或已通过真实用户验收。

## 11. 目标体验一句话

**Saytile 应像一块安静地陪伴用户的文字空间：用户自然开口，文字就在眼前出现；控制只在需要时轻轻存在。**
