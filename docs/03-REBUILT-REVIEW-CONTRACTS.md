# 中断修订的重建契约

来源是恢复包 `UNPUBLISHED_REVIEW_DELTAS.md` 及用户截图里的审查摘要。本轮代码是按照约束重建的实现，不是前一位 Pro 未上传文件的逐字恢复。

## R1 · 删除原音，保留文字

动作一：`deleteAudioKeepingText`。保留 utterance、所有 transcript revisions、用户选中的修改稿、搜索/复制/复用能力。原音回放与重识别不可用。

动作二：`deleteRecord`。删除整条记录，包括文字与原音。与动作一使用不同的确认文案、接口和恢复记录。

删除原音先在一个事务中写入 `audio_erasure_intents`、音频范围/块快照，令 `audio_state=delete_pending` 并递增 `audio_epoch`，取消依赖这些原音的未完成任务；不递增文本 `content_generation`，不插入整条记录删除墓碑。ASR 迟到结果校验 source_audio_epoch 后丢弃。

物理清理后才标 `complete`。恢复扫描先读音频删除意图，减去删除范围，再考虑孤儿文件；不能因看到文件又重新挂回已删除的音频。

### 共享块与崩溃

若文件还被另一条正常记录或活跃播放器/识别任务使用，参考模型保留它并返回 `shared_deferred`/`leased`。界面不能显示“物理清理完成”。原生产品可在低优先级维护队列中复制存活区间、同步、替换引用、删除旧文件；这一步尚未实现。

若 unlink 已发生而数据库尚未提交，恢复后重复清理是幂等的。单次未完成的清理不删除任何文字。删除意图不因文件暂时不存在而撤销。

主动删除和自动整理也不同。自动整理保护收藏、未识别/失败原音、活跃租约；用户明确选择删除时允许删除自己的收藏原音。删除正在录的段落先封段，以新段继续，不用无限开放的删除范围。

本轮没有实现安全擦除 SSD、系统备份或云备份，不能宣称取证级永久抹除。

## R2 · 稳定前缀只派发一次

稳定文字来自识别器的范围/最终确认适配，不来自“又来了一个 revision”。游标以 `(binding_id, utterance_id)` 为边界，保存已派发 UTF-16 终点及准确文本快照。

一次自动派发：确认运行时绑定有效 → 校验稳定 UTF-16 边界 → 在同一 IMMEDIATE 事务中核对已派发前缀 → 预留未发后缀并登记 dispatching → 更新游标 → 提交 → 原生层在实际操作前再检查目标 → 最多尝试一次 → 记录确认/未确认/失败。

示例：`你好` → `你好，世界` → 相同结果再次到达，实际只派发 `你好` 与 `，世界`。如果 `你好` 已发，后续变成 `你们好`，暂停这个绑定的自动追加并保留版本，不盲目追加整句，也不修改目标全文。

UTF-16 不是 Python 字符数，也不是 Swift Character 数。`你😀` 长度为 3 个 UTF-16 code units；偏移 2 切断代理对，必须拒绝。原生层还应结合编辑器和输入法组合文本边界，不宣称本轮覆盖所有 grapheme/IME 场景。

重启：dispatching → unverified；prepared → cancelled；旧绑定全部失效。已不确定的操作不自动重放。新一次明确绑定与新的独立段仍可继续；不建立“有一条 UNKNOWN 就停掉整个系统”的门槛。

重新绑定不自动排队旧历史。本轮参考模型验证派发账本，原生调度层仍需确保只有之后的新讲话自动进入目标；历史复用必须是明确操作。

## 验证对应

37 项契约测试覆盖原音独立删除、修改稿保留、搜索、晚回调、重启、共享块、租约、保留政策、越界文件路径、重复 revision、前缀改写、UTF-16、未确认投递、目标失效与 SQL 游标保护。测试名称和结果在 `tests/test_recovery_contracts.py` 与 `evidence/rebuilt-contracts.log`。
