# PR #18 前台输入验收

基线 `76adc6875fd365fd8d7f70a1d2a23a520255be6d`，生产 `Sources` 树 `686367164b771ee875e7cee0d4dd218de1930710`。本次变更限于隔离测试与收据。个人体验安装仍为 build 269，所有投递使用临时合成文档。

## 两次历史失败

- 第一次运行中，Chrome 首次写入和重复抑制通过，追加的组合断言失败。旧程序没有分别输出投递状态、AX 整框读回或页面收到的输入事件，无法反推出是未确认、字段不符还是两者同时发生。WKWebView、AppKit 和 TextEdit 通过。[完整作业](https://github.com/haohongfei2001-png/saytile/actions/runs/43092162807/job/130771737246)
- 第二次运行中，WKWebView 在预留投递后的最后一次目标检查取消，未进入外部写入，也没有绑定观察回调。随后同一 DOM 保留原文，光标为 UTF-16 7、选区长度 0。没有外部应用抢占焦点的记录。启动阶段的拼写服务超时早于此次取消，旧收据没有保留失效瞬间的 AX 字段。[完整作业](https://github.com/haohongfei2001-png/saytile/actions/runs/43092162807/job/130778634807)

## 本机复现与修复

基线在独立 WKWebView 的稳定页面、40 个附加节点并施加短时 GUI 负载的页面、负例后重新建立的独立稳定目标中，三次均只写一次并得到确认。在第二次目标读取前，分别让同一网页变更标题内容、让目标主线程短时无法处理 AX 读取，两次均出现原错误形态，投递取消、零写入、零发送。暂时不可读的用例恢复响应后，完整目标和原文再次相同。历史失败不能再细分到唯一字段。[本机机器收据](../evidence/pr18-foreground/local.json)

旧测试在启动后又主动取回前台焦点、重设选区；准备判定只比较快照，没有观察尚在传递的焦点、布局和选区事件。现在每个目标只执行一次初始激活，设置阶段用生产 AX 观察器与相同的三次完整证据检查等待窗口就绪。建立绑定后，所有投递仍沿生产路径执行一次。两个确定性的 WKWebView 负例在 SQLite 预留后、实际写入前改变目标的可验证性，分别检查取消、原文、光标和零发送。

Chrome 使用专属临时配置与唯一合成文件。页面在真实 `input` 事件中记录首次和追加是否依序出现，探针单独核对生产结果、写入次数、AX 全文、DOM 全文、光标和发送次数。首次确认、重复调用与追加之间没有插入等待或 DOM 检查。另测用户移动选区、等长度手改、切换到同页另一个编辑器、显式取消。AppKit 覆盖忽略写入后不重放、用户手改、取消和另一窗口。任何正例未确认都会让作业失败。

## 验收范围

本机两个真实前台窗口通过 10 项主断言和 11 项独立边界场景。最终 GitHub 完整五项作业及 Chrome 真实结果按 PR head 核对，原始作业附件中的 `source.txt` 记录对应提交。个人数据目录仅核对元数据。正式发布、签名公证与云端识别不属于本次输入验收。[PR 检查](https://github.com/haohongfei2001-png/saytile/pull/18/checks)
