# 原生工程接续

## 当前可以开始什么

可以从现有设计开始一个范围明确的原生 P0，不必重新做竞品调研或重命名。

第一条纵向路径：菜单栏 → 明确授权 → AVAudioEngine 采集 → VAD → 独立原音日志 → 一个主 ASR 适配器 → 输入板 → 复制。先测录音/识别分离，不能因为 UI 好看就跳过原音恢复。

第二条路径：文字/原音历史 → 编辑版本 → 只删原音 → 崩溃恢复 → 搜索/复用。把本轮 37 项模型契约移植为原生单元/集成测试。

第三条路径：一次明确目标的主动插入 → 运行时绑定和失效 → 稳定前缀派发账本 → 连续直接输入 → 真实 ChatGPT/Claude SPA 目标切换。无可用目标时留在板内；不让输入失败拖住录音。

最后才扩展生命周期、长期功耗、压缩归档、签名更新与公开发布。V2/V3 不在此列表。

## 复用边界

优先复用 AVAudioEngine/Core Audio、系统 Speech 与成熟 WhisperKit、FluidAudio/Silero、SQLite/GRDB、NSPanel、NSStatusItem、SMAppService。先锁定实际版本与许可，再集成；不要复制整个竞品的代码来替代设计实现。

不搭建账号服务、通用 Agent 框架、复杂事件总线、多引擎并行编排或私有“认证协议”。一进程、少量 actor/队列足以启动验证。

## 需要交接的事实

`archive/` 是历史证据；`contracts/`、`model/` 和 `prototype/` 是本轮重建/修订；没有真实原生 App 已经交付。

本地参考模型对共享文件采用延期，不实现存活区间重写。生产实现必须在可验证的维护流程中补齐，不能把删除索引当作物理删除。

原型的本地示例持久化不是生产存储；SQLite 模型是算法验证，不应成为 Mac App 的 Python 运行时依赖。

## 防止再次丢失

每完成一个可独立验证的切片，提交源码、测试、STATUS 与下一步。PR 中写明已运行命令、真实测试环境、剩余限制。不以“准备上传”结束，也不在所有工作完成前长期只保留临时文件。
