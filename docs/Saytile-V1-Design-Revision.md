# Saytile · V1 产品与技术设计

恢复修订版 · 2026-11-06

# 产品与三版本路线

## 产品定义

Saytile 是始终待命的个人 AI 语音输入与表达工作台。自然开口、连续记录、失败可找回，文字随时进入正在使用的软件。产品价值是减少表达过程中的启动、等待、重复说话和反复复制，而不是宣传某一种识别技术。

“始终待命”指用户授权并开启后，应用在可用会话中持续接收音频；不代表关机、睡眠、权限失效或磁盘故障仍可录制。采集状态必须可见，暂停随时可用。

## 版本承诺

V1：持续采集、实时/低延迟转写、独立原音保存、语音历史、编辑/重识别、复制/插入、失败恢复与长期运行质量。

V2：低音量讲话、近讲麦克风、工位干扰等轻声能力的独立研究和实现。V1 不承诺耳语效果，不增加未验证的“静音识别”开关。

V3：文字输入法、个人词库，以及用户授权的 PAIA、备忘录、文档等语言适应。V1 不建立外部资料索引、词库导入或系统输入法框架。

## V1 默认体验

第一次解释持续使用麦克风后，由用户开启自由记录。此后不逐句开启，关闭输入板不停止采集。未授权辅助功能时，记录、浏览、搜索、回放和复制仍可使用。

自由记录：文字留在输入板，用户编辑并一次插入或复制。

直接输入：用户在目标草稿中明确开启一次，后续稳定新段落进入该目标。已存在的历史内容不因重新绑定而自动重发。目标或选区改变时，保留内容并暂停自动输入；不自动发送。

历史复用：搜索文字、回听原音、复制/带回输入板。删掉原音后，文字、修改稿、搜索、复制仍可用；回听和重新识别明确不可用。

## 三层界面

菜单栏显示全局待命、收音、暂停、可恢复问题和采集失败。不要试图用一个颜色同时表示所有段落的保存/识别/输入状态。

即时输入板保持固定范围，文本可滚动；阅读旧文或选字时停止跟随，新内容不抢焦点。每段的原音保存、识别状态和输入结果分别反馈。

语音档案以文字为主，按时间组织。原音是独立、可管理的内容，不是识别成功后即可丢弃的缓存。

## 保存政策修订

建议默认“保留至手动删除”，10 GB 作为提醒阈值，而非自动删除许可。允许用户明确开启按期限/空间整理，执行前展示受影响记录。待识别、识别失败、收藏及正在使用的原音受保护。

这不是无限存储保证。磁盘不足时须明确暂停无法持久化的新采集，并保留已存内容。后续可用 ALAC 背景压缩降低空间，但不能依赖压缩成功才能保存原音。ALAC 尚未实机实现或验证。

## 非目标

V1 不做账号云同步、会议多人归属、屏幕采集、强制声纹、语音 Agent、自动发送、每句 LLM 改写，也不把“仅限本地”当产品宪法。


# V1 技术架构与复用

## 继承基线，不重做研究

原完整研究保存在 `archive/recovery-source/Always_On_Voice_Design.pdf` 及其技术附件。它提出 SwiftUI/AppKit、AVAudioEngine/Core Audio、FluidAudio/Silero、Apple Speech、WhisperKit、SQLite/GRDB、Accessibility 等路线。本轮没有重做模型竞赛，也没有重新验证其历史版本号、全部许可证或市场资料。

首个工程候选继续使用 Apple SpeechAnalyzer/SpeechTranscriber；WhisperKit 为替代路径。理由来自原报告的系统集成与维护成本判断，而不是已证明中文识别最优。启动正式工程时核对 SDK、中文语言资产和依赖版本，并用同一批普通话、中英混说、数字、否定词和专业词样本比较。

若候选不达标，应允许有明确授权的在线或混合 ASR，而不是为“本地优先”牺牲体验。V1 不为这个可能性先实现多套推理系统；只保留 SpeechEngine 的能力和处理位置边界。

## 数据通路

麦克风 → 有界音频缓冲 → VAD/保留范围 → 原音日志与流式识别并行 → 文本版本库 → 输入板/历史 → 独立输入操作。

保存责任与实时识别可以并行，不必整段录完才出字。“原音已保存”只依据真实持久化水位。ASR、UI 或目标应用失败不能停止后续音频落盘。

实时回调不写磁盘/数据库、不等待 ASR。文件分块、识别会话和视觉段落是不同边界。原报告的 1 秒预录、800 ms 尾静默、15 秒物理块、1 秒同步均只是 P0 起点，不是实测保证。

## 当前可执行资产

- `contracts/schema.sql`：原结构加独立音频删除意图、audio_epoch、派发绑定/游标/快照与保护约束。
- `contracts/Contracts.swift`：Foundation 可编译接口；含设备/在线引擎边界、独立音频删除协议和 DirectDispatchLedger。
- `model/reference_store.py`：SQLite 与合成文件上的设计参考模型，用于验证事务和恢复语义；不是生产音频实现。

不把 Python 模型嵌入正式 Mac App。原生版复用同一契约，以 Swift/GRDB 实现。不要因本轮已有参考代码就绕过真实音频工程。

## 输入集成

先做明确目标的主动插入，再做连续直接输入。使用目标控件支持的局部插入或原生粘贴，不读取全文再覆盖。不发 Return、不发送消息、不清除已有附件。

运行时目标由应用、窗口、编辑控件、绑定会话和必要的页面语义共同界定。数据库里只保存审计标识；重启后不能用标签重建可执行目标。SPA 切换可能复用编辑节点，原生验收必须验证，不以元素句柄不变判定聊天没变。

复制成功、已尝试投递、确认插入分开。只有有可靠局部结果证据时才显示“已插入”。不能可靠确认时保留文字，允许后续独立段继续；不自动重发。

## 重要取舍

SQLite 事务可以原子更新本地派发意图和游标，不能与外部应用粘贴形成跨应用原子事务。因此本设计追求范围级“至多一次自动尝试”，不是“恰好一次交付”。崩溃发生在记录派发后、实际粘贴前，可能需要用户主动复用该段；不能用自动重试掩盖风险。

本轮查阅的 SQLite 事务文档明确支持 IMMEDIATE 写事务与单写者模型；参考实现据此在同一事务内校验/预留，而不是先检查再单独写入。参考：https://www.sqlite.org/lang_transaction.html 。Apple isFinal/NSRange 官方入口见来源索引；其完整动态正文未在本轮重新取得，不把历史解释标成此次全面复核。


# 中断修订的重建契约

来源是恢复包 `UNPUBLISHED_REVIEW_DELTAS.md` 及用户截图里的审查摘要。本轮代码是按照约束重建的实现，不是前一位 Pro 未上传文件的逐字恢复。

## R1 · 删除原音，保留文字

动作一：`deleteAudioKeepingText`。保留 utterance、所有 transcript revisions、用户选中的修改稿、搜索/复制/复用能力。原音回放与重识别不可用。

动作二：`deleteRecord`。删除整条记录，包括文字与原音。与动作一使用不同的确认文案、接口和恢复记录。

删除原音先在一个事务中写入 `audio_erasure_intents`、音频范围/块快照，令 `audio_state=delete_pending` 并递增 `audio_epoch`，取消依赖这些原音的未完成任务；不递增文本 `content_generation`，不插入整条记录删除墓碑。ASR 迟到结果校验 source_audio_epoch 后丢弃。

物理清理后才标 `complete`。恢复扫描先读音频删除意图，减去删除范围，再考虑孤儿文件；不能因看到文件又重新挂回已删除的音频。

### 共享块与崩溃

若文件还被另一条正常记录或活跃播放器/识别任务使用，参考模型保留它并返回 `shared_deferred`/`leased`。界面不能显示“物理清理完成”。原生产品可在低优先级维护队列中复制存活区间、同步、替换引用、删除旧文件；这一步尚未实现。

若 unlink 已发生而数据库尚未提交，恢复后重复清理是幂等的。单次未完成的清理不删除任何文字。删除意图不因文件暂时不存在而撤销。

主动删除和自动整理也不同。自动整理保护收藏、未识别/失败原音、活跃租约；用户明确选择删除时允许删除自己的收藏原音。删除正在录的段落先封段，以新段继续，不用无限开放的删除范围。

本轮没有实现安全擦除 SSD、系统备份或云备份，不能宣称取证级永久抹除。

## R2 · 稳定前缀只派发一次

稳定文字来自识别器的范围/最终确认适配，不来自“又来了一个 revision”。游标以 `(binding_id, utterance_id)` 为边界，保存已派发 UTF-16 终点及准确文本快照。

一次自动派发：确认运行时绑定有效 → 校验稳定 UTF-16 边界 → 在同一 IMMEDIATE 事务中核对已派发前缀 → 预留未发后缀并登记 dispatching → 更新游标 → 提交 → 原生层在实际操作前再检查目标 → 最多尝试一次 → 记录确认/未确认/失败。

示例：`你好` → `你好，世界` → 相同结果再次到达，实际只派发 `你好` 与 `，世界`。如果 `你好` 已发，后续变成 `你们好`，暂停这个绑定的自动追加并保留版本，不盲目追加整句，也不修改目标全文。

UTF-16 不是 Python 字符数，也不是 Swift Character 数。`你😀` 长度为 3 个 UTF-16 code units；偏移 2 切断代理对，必须拒绝。原生层还应结合编辑器和输入法组合文本边界，不宣称本轮覆盖所有 grapheme/IME 场景。

重启：dispatching → unverified；prepared → cancelled；旧绑定全部失效。已不确定的操作不自动重放。新一次明确绑定与新的独立段仍可继续；不建立“有一条 UNKNOWN 就停掉整个系统”的门槛。

重新绑定不自动排队旧历史。本轮参考模型验证派发账本，原生调度层仍需确保只有之后的新讲话自动进入目标；历史复用必须是明确操作。

## 验证对应

37 项契约测试覆盖原音独立删除、修改稿保留、搜索、晚回调、重启、共享块、租约、保留政策、越界文件路径、重复 revision、前缀改写、UTF-16、未确认投递、目标失效与 SQL 游标保护。测试名称和结果在 `tests/test_recovery_contracts.py` 与 `evidence/rebuilt-contracts.log`。

# 原生工程接续

## 当前可以开始什么

可以从现有设计开始一个范围明确的原生 P0，不必重新做竞品调研或重命名。

第一条纵向路径：菜单栏 → 明确授权 → AVAudioEngine 采集 → VAD → 独立原音日志 → 一个主 ASR 适配器 → 输入板 → 复制。先测录音/识别分离，不能因为 UI 好看就跳过原音恢复。

第二条路径：文字/原音历史 → 编辑版本 → 只删原音 → 崩溃恢复 → 搜索/复用。把本轮 37 项模型契约移植为原生单元/集成测试。

第三条路径：一次明确目标的主动插入 → 运行时绑定和失效 → 稳定前缀派发账本 → 连续直接输入 → 真实 ChatGPT/Claude SPA 目标切换。无可用目标时留在板内；不让输入失败拖住录音。

最后才扩展生命周期、长期功耗、压缩归档、签名更新与公开发布。V2/V3 不在此列表。

## 复用边界

优先复用 AVAudioEngine/Core Audio、系统 Speech 与成熟 WhisperKit、FluidAudio/Silero、SQLite/GRDB、NSPanel、NSStatusItem、SMAppService。先锁定实际版本与许可，再集成；不要复制整个竞品的代码来替代设计实现。

不搭建账号服务、通用 Agent 框架、复杂事件总线、多引擎并行编排或私有“认证协议”。一进程、少量 actor/队列足以启动验证。

## 需要交接的事实

`archive/` 是历史证据；`contracts/`、`model/` 和 `prototype/` 是本轮重建/修订；没有真实原生 App 已经交付。

本地参考模型对共享文件采用延期，不实现存活区间重写。生产实现必须在可验证的维护流程中补齐，不能把删除索引当作物理删除。

原型的本地示例持久化不是生产存储；SQLite 模型是算法验证，不应成为 Mac App 的 Python 运行时依赖。

原有 10 项实验按原文件复跑，证明历史实验仍可执行，不作为所有新语义的判据。例如旧实验允许一个 prepared 操作留待处理；当前正式规则与新增测试要求进程重启时取消 prepared，以防旧绑定重放。
