# 0.17 · 自然段复制

基于当前安装的 0.15（484）`ab8545507c79640ec3f419e33467a0263c154844`，独立分支 `codex/paragraph-copy`。未采用的 0.16 ASR 改动不在本分支，识别数学与运行库沿用现用版本。

## 产品规则

- 语音板没有选区时，左下复制键只复制最新有文字且未清空的一个自然段。时间组可以包含多段，不再作为复制范围。
- 有选区时立即复制选区，可跨段；保留 Unicode、用户文字和手工换行。
- 主板与档案共用 `paragraphID` 和 `paragraphCopy`。自然讲话间隔达到 15 秒开始新段，默认 60 秒形成时间组，仍按原规则；本轮没有调整时间阈值。
- 一段跨多个 ASR 录音、跨 64 条 UI 分页仍完整复制。点击时固定末尾位置，明确清空之前的内容不会被带回。新空白录音不会抢走最新有效文字的复制目标。
- 屏幕上已显示的文字优先于尚未显示的后台修订；复制立即形成快照，后续识别不改写剪贴板。
- 用户手工插入/删掉换行保留排版结果，不重新划分档案原音单元；换行排版与自然讲话段落身份不同。跨段取用可选择文字，不把一整时间组默认为一段。
- 不改外部输入的范围账本、录音、数据库格式或主板控件。

## 实际验证

旧 AppModel 在新增的同时间组双自然段检查中失败：它复制了两段。修复后 AppModel 183/183 与原生窗口手势检查通过；自然段、时间轴与段落文档 Swift Testing 18/18 通过，含 12,001 条历史的有界读取和 135 条成员的完整复制。未放宽既有断言。

最终源码的真实签名语音板按钮/档案菜单、升级回退与完整 CI 尚待执行，完成后另附同源收据。没有操作系统剪贴板、用户数据库、真实录音、云 API 或麦克风；Mac 按要求保持合盖。不合并 main、不公证、不公开发布。

首轮签名原生运行中，同组双段的按钮/菜单复制、emoji 选区及剪贴板快照通过。其后发现验收程序选区操作留下历史分页位置，下一独立场景等待第四条记录超时；现通过原生文字视图的“回到最新”动作复位后继续。产品清除选区不自动抢夺阅读位置的行为不变。该次失败日志保留，最终同源原生回归另附。
