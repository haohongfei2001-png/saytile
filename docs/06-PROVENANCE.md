# 来源与恢复边界

## 原件来源

本轮在实际工作目录读取了 `Saytile-Recovery-2026-11-06.zip`、`Always_On_Voice_Handoff.zip`、独立 PDF 和 HTML。恢复包中的原始文件在 `archive/recovery-source/` 按字节复制，`archive/Always_On_Voice_Handoff.zip` 为先前交接压缩包原件。

存在三个字节不同的 PDF：恢复包 PDF 836,599 字节；独立 Library PDF 836,589 字节；旧交接 ZIP 内 PDF 811,597 字节。它们分别保留，不声称是同一个哈希或把任一版本冒称最新未发布修订。原型 HTML 86,807 字节与旧交接包中的版本一致。

## 重建依据

用户截图与恢复清单支持两条规则：仅删原音保留文字；连续输入跟踪已派发稳定范围。旧 Pro 后续的 SQL/Swift/HTML 原件没有找回，因此本轮在保留基线的前提下自行实现对应修改。

旧恢复清单中的“回到原会话”“先确认 Private”属于当时历史建议，已被当前事实覆盖：旧会话已满，用户明确同意公开。这些原件不改写；当前执行规范见 AGENTS.md。

## 证据优先级

当前用户版本边界 → 本轮修订文档及测试 → 原始基线研究。原件保留历史，不覆盖用户后来明确决定。

测试证据由本轮命令实际生成。原 Pro 所说 12 项保留整理、33 项 UI 测试不作为本轮验证凭据。本轮使用独立的 37/48 计数，不伪称复现了那些找不到的脚本。

## 外部资料边界

历史 `SOURCE_URLS.txt` 原样保留，不代表本轮逐一复查。当前没有重新发布竞品/价格/商标结论。SQLite 事务正文已本轮查阅；Apple 官方 isFinal、NSRange 入口可达，但动态 Markdown 正文未由检索工具成功展开。Swift UTF-16 用实际 Foundation 断言检验，而非猜测。

## 哈希

`archive/SOURCE_HASHES.json` 记录恢复源和复制件的 SHA-256。根目录 `SHA256SUMS.txt` 对当前交付文件逐个校验，不包含自身及 `.git/`。生成新证据后要重新生成清单。

原有 10 项实验按原文件复跑，证明历史实验仍可执行，不作为所有新语义的判据。例如旧实验允许一个 prepared 操作留待处理；当前正式规则与新增测试要求进程重启时取消 prepared，以防旧绑定重放。
