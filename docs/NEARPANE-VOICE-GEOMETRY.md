# Saytile / Nearpane｜独立语音板的尺寸与位置统一

**状态：2026-11-12 用户新决定的实现规范。** 对照 Nearpane 现行默认值：侧栏占可用屏幕宽 12.5%，语音模块占可用屏幕高 22.5%，全侧栏高 100%。

Saytile 是 Nearpane 中语音模块的独立形态。独立版只有语音内容与两枚操作按钮；没有 Nearpane 的纵向外框、截图托盘、空间调度和其他模块。窗口几何承接 PR #20。两个宿主通过 SaytileVoiceUI 使用同一份白色玻璃、连续文字和底部操作控件。

## 统一默认（AppKit 逻辑点）

- 取主显示器的 NSScreen.visibleFrame，排除菜单栏和 Dock，不用物理像素或全屏 frame。
- 以**可见玻璃内容**为准：宽度 = visibleFrame.width × 0.125；高度 = visibleFrame.height × 0.225。
- 可见玻璃的右上角 = visibleFrame 的右上角（与 Nearpane 的顶部/右侧基准一致）。
- 窄屏直接使用侧栏分配宽度，文字、内边距和控件由共享视图响应式排布。例如可用宽 1280pt 时语音区宽 160pt。
- 原有 32pt 透明投影区不计入宽高；贴边时允许投影在显示器外被裁切。禁止把 NSPanel 的透明边距错误地当成产品内容宽度。
- 原图的 344 × 234pt 玻璃和 408 × 298pt 参考渲染窗口**仍保持不变**；用于原设计比对，不能将参考尺寸当成所有屏幕的首次尺寸。

## 交互及产品边界

- 先恢复 v3 的手动位置；若只有旧 v2 的手动位置则沿用它。没有手动记录时使用统一的右上角默认位置。之后的拖动和双向缩放写入 v3，v2 可供回退。
- 显示器拔插时只作可见屏回退；原显示器回来可按既有偏好还原。屏幕可用区尺寸改变时，按玻璃区域的相对位置重映射，而不是按透明窗口外框计算。
- Nearpane 用户自定义的侧栏宽度、语音高度、位置属于 Nearpane 自己的设置。两个产品的共同默认不意味着读取、写入或联动对方的独立偏好。
- 保持两个独立 App 与数据目录，不混合音频资料、权限、服务或独立运行生命周期。Nearpane 的实际模块仍由 Nearpane 自己的宿主承载。

几何回归见 tests/SaytileKitTests/WindowPlacementTests.swift；原生桌面视觉一致性需要单独在真实 macOS 多屏环境确认，不能用单元测试代替。
