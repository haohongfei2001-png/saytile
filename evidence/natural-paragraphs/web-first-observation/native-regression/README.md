# Independent input-gap safety review

The one product change under review is `observedOwnWebEdit` treating the first `snapshot()` unsupported exception during an already-issued, continuously bound, independently observable web insertion as an unread interval. It does not assert ownership. It delegates to the existing bounded readback path, which requires two new identical target/caret/whole-field witnesses after the gap. A second observed content/selection change, focus/page change, or layout change invalidates the binding. Correction and manual modes cannot enter this path. No additional write, paste, key event or focus reacquisition was added. No new P0/P1 found in this change.

`owned-range-summary.json` and `owned-range-probe.log` document 9/9 real background native AX scenarios with exact fixture PID/nonce. `background-evidence/` contains the existing AppKit and WKWebView default nonactivating fixture logs. The latter runs reused the exact newly built library from the owned-range script; only the temporary wrapper configures this library path, and the repository driver functions/assertions are unmodified. Native WKWebView observed-change checks are 6/6. The foreground app did not change and no owned fixture became key or main; no keyboard, clipboard-paste, Enter/send or full-field writes occurred.

This work did not launch visible Chrome or certify the actual foreground Chrome snapshot-gap path. CI performs that acceptance. The new deterministic unknown-snapshot regressions are owned separately by the test agent and are not inferred from these background results. No installed app, microphone, ASR, private text or production store was used. All probe source/library hashes are captured in the machine receipts.
