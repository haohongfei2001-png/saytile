Final product source 9aace8f5b0d7082bd67d2e9b1b6e1db6dcf05883, signed worker hash in ../binary-and-corpus.json. Five public FLEURS inputs from the original pinned paired.json manifest were replayed through CaptureWorker → PCMJournal → the same Qwen → SingleTranscriptEngine. All five signed model processes exited 0 and emitted `kind=final`, empty `text`, with the exact input frame count. Therefore these five empty results were already empty at the model boundary; they were not discarded by this change to LocalLiveText. No second recognizer ran in the product.

Low energy is NOT proof of silence or permission to mark success. The aggregate source references have complete Chinese text in the other segment, with the pre-existing foreign-name/FTIR errors still included in CER. Whether these extra segments contain speech is not human-verified; no filtering, empty-success reclassification or VAD tuning is made on this evidence. Original audio remains recoverable. Product handling remains failed/retryable, not falsely completed.
