## Same-run resource measurements

`scripts/mandarin/measure-preview-cost.py` runs one signed automatic AppKit panel through one hash-checked public file on wall-clock time in a private temporary archive. The same run records raw decodes, timeline publications, AppKit content, final text, combined simultaneous physical footprint, and cumulative CPU time for the app and each unique helper. The last sample can miss work in the final fraction of a second before exit. Startup, setup and EOS are included. The accumulated time is CPU time only; MLX decoding wall time can overlap GPU work. Host power samples from an unrelated run cannot determine this run's battery impact.

The 442 baseline on the public 38.8-second continuous sample consumed 2.61 app CPU seconds and 15.69 helper CPU seconds in 40.33 seconds of wall time, or about 0.454 CPU cores averaged over the whole process run. Its 73 preview decodes occupied 20.615 seconds of worker wall time. Simultaneous app and helper physical footprint peaked at 1,659 MiB. The probe observed completed final archives and laid-out text in the same native window. It also found a 3.088 s publication gap from 26.525 to 29.614 seconds despite five intervening worker updates. The first withheld result advanced into the next clause while replacing a comma with a double em dash and another comma with a period. The second briefly rewrote a lexical phrase before the third returned to the original words. [Run measurements](baseline/continuous-cost/process.json)

`scripts/mandarin/compare-preview-cost.py` compares identical utterances across source-bound native receipts. Its immediate-suffix revision count agrees with the original native scoring and it separately counts the normalized characters actually deleted or substituted by minimum edit distance. Real publications, screen appearance, raw compute time, and CPU time are separate measurements.
