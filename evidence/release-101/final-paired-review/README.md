## 904.8 秒长时测试的真实边界

独立在内存重建公开夹具，SHA-256 与原报告完全匹配：`59803d4dab449d25256a9338aaf176000dff0dc5287e334241b4b16990b0defc`。没有重新运行识别。

**实际通过范围：** 自动 Qwen 路由、904.830375 秒输入、44/44 记录 completed/available、80 个已保存音频块可读、PCM 按原输入顺序匹配、SQLite integrity ok/无外键错误、44 条时间轴关联、0 次外部派发。记录中保存的音频为 814.050375 秒，包含 VAD 保留的部分静音。

**不能扩大成以下结论：**

- 该夹具为 72 次公开片段（16 个不同样本，共 787.830375 秒原 PCM）加 72 秒分隔静音及 45 秒插入静音；不是 15 分钟不间断自然讲话，也不是现场麦克风。
- 测试确认每个片段都有已完成记录的音频覆盖，断言为 `completed_frames > 0`。VAD 会省略静音；不能从该断言推导“每个人声帧均未丢失”，也没有对长时拼接稿重新计算 CER。它不能抵消完整 440 集合的五个失败子段。
- UI 计数为 2,135 次文字变化，但原生探针只保留前 512 个文字帧。可以证明实际发生了很多更新，不能用这份收据证明最后数分钟最大显示间隔或“全程零冻结”。
- 成功后原临时 SQLite/原音目录已由测试程序清理。本次可验证重建夹具 SHA 和已保存收据，无法重新打开原成功运行的数据库与所有录音块。不得声称再次逐文件复验了已清理的档案。

资源采样每约 5 秒一次：App CPU 中位数 5.1%、worker 23.6%；**两个独立中位数不能相加当作同时总 CPU 中位数**。App 峰值 RSS 118.31 MiB，worker 805.38 MiB；前/后 5 分钟 RSS 中位数分别为 112.19→113.52 MiB、757.06→759.17 MiB。没有明显的该时长内 RSS 单向增长迹象，但这不是无限时长泄漏证明，亦非 footprint、GPU/ANE、整机内存压力或功耗测量。

45 秒空闲窗口为输入时间 483.4101875–528.4101875 秒。收据保留两次较晚的无子进程采样（519.347、524.387 秒），之后再次观测到子进程，后续片段均有 completed 音频覆盖，支持“空闲退出、后续识别恢复”的有限通过。完整逐次进程样本未保留，进程采样与 `LocalStreamProbe` 起点也不同，不能用这份聚合收据宣称精确 35 秒释放或某个确定的重新加载延迟。
