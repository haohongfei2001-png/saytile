# EOS experiment independent static review

Base: `0fbca1d892bbc8aa550c4439b8cfcb045af825ae` (476). Experimental helper SHA-256: `d3eb98f6dc98ddedbbe67d150f166da843f545cacbc5b2de818ccded8976bd83`. Reviewed source hashes are in `static-review.json`. This review ran no model, microphone, foreground UI or private-data test.

**Conclusion:** no new structural defect found in state reset, current-audio ownership, short exact-PCM reuse, 32-second boundary, user-edit or dispatch protections. This does **not** establish final-text equivalence or quality. Moving block verification into EOS changes its numerical computation shape, so the original scalar-greedy final guarantee is intentionally no longer available on that branch. Acceptance must come from the unchanged same-audio quality and native contract checks; speed alone cannot pass it.

## State and audio

- `Worker.swift:56–61`: every nonverified decode clears token proposals before entering the model. `Qwen3ASR.swift:524–530` constructs a fresh nil KV cache and complete current-audio prefill for every call; only token IDs, not prior PCM embeddings or KV, survive.
- `Qwen3ASR.swift:544–572`: the proposal is removed before decoding; eligible calls save only their newly generated IDs. A proposal shorter than 16 tokens falls back to ordinary greedy. If first current argmax differs, no token is accepted. After a partial block mismatch the cache is cropped to the matched prefix and greedy resumes at the mismatch (`744–780`). The multi-token decoder creates an offset-aware causal mask (`QuantizedTextDecoder.swift:220–235`), so rejected future draft tokens cannot leak backwards through attention.
- After a verified EOS, its ID array remains until the next decode. This is bounded and is not used across utterances: final resets `last`, `samples`, `frames`, `prefix`, `next`, and `exactPreview` (`Worker.swift:156–163`). The next utterance's first nonempty decode has `last == ""`, forcing the scalar closure to clear IDs before inference. A zero-frame next EOS emits empty text without consulting the model; the host rejects that as incomplete, and a subsequent nonempty first decode still clears IDs. No cross-utterance counterexample was found.
- Current PCM is append-only within the worker. The framed reader consumes zero-length EOS as a distinct packet. Backlog draining cannot bypass EOS because its coalescing guard explicitly requires `!end`. A thrown read/decoder error exits the helper before a final event; the unchanged host stops it and marks recognition failed. Audio persistence lives outside this process and was not modified.

## Exact PCM and 32-second boundary

- `Worker.swift:115–116,139`: only an earlier **scalar** decode can populate `exactPreview`; a verified preview clears it. Reuse additionally requires exact total frame equality. Adding even 320 frames invalidates it. A scalar first hypothesis that happens to arrive after 3 seconds can still be reused if EOS adds no PCM; that is safe because its input and computation were already original greedy. `diagnosticFinalVerified` remains false on this shortcut.
- At a 32-second boundary, `samples.count < windowLimit` is false, so the boundary remains original greedy and clears any proposal. Only this confirmed tail is appended to `prefix`; the sample window is then emptied. If EOS follows immediately, the scalar exact-PCM result is reused. If another tail arrives, only that new tail is re-encoded and appended after the confirmed prefix. A first post-boundary call with no saved proposal falls back to scalar even if the worker still has a nonempty prior display string.
- The existing worker processes the packet crossing 32 seconds as a whole; this experiment does not alter that pre-existing packet/window convention. Normal capture segments are bounded below that limit. This review does not claim a new proof for arbitrary oversized diagnostic packet boundaries.

## Completion, edits, copying and external input

- `LocalASRProvider.swift:202–226` remains unchanged: event order and monotonic frames are checked, sender completion is awaited, nonempty final text is required, and errors stop the worker. Final text is sent through the same candidate ingress. The diagnostic flag is not a recognition-complete or acoustic-confidence signal.
- `LocalLiveText.accept` still grants Qwen previews zero stable UTF-16 length; only final enters the stable path. The experiment does not turn verified preview IDs into early dispatchable text or introduce a second recognition engine.
- `LocalCandidateIngress.swift:23–43` still uses the active recognition ticket, candidate sequence and fusion publication, and only completes after nondeferred final publication.
- `Store.swift:1346–1347` prevents automatic revisions from replacing either a selected user-edit revision or an in-progress editing draft. Archive versions are inserted separately; frozen/copied revisions remain protected from preview pruning. `AppModel.swift:1423` avoids overwriting the open edited draft during refresh.
- `Store.swift:706–744` retains stable UTF-16 suffix reservation, exact dispatched-prefix checks, duplicate no-op behavior, stale/late revision rejection and durable reservation before a write. Existing target/caret/window ownership validation in `InputCoordinator` is unchanged. Owned corrections still exclude local user edits and drafts (`Store.swift:1414–1421`) and consume target ownership before any ambiguous mutation. No auto-send path is added.
- The Swift host's current `WorkerEvent`/`WorkerDecodeTiming` decoder ignores the new optional `diagnosticFinalVerified` key. Direct helper JSON retains it. Native timing evidence must use the retained `final == true` plus `verifiedPreviewTokens > 0` to establish actual EOS block use, or capture the raw helper event. A true diagnostic flag alone can include a zero-token scalar fallback and is insufficient evidence.

## Remaining quality risk / release gate

The verified path checks every accepted proposal ID against the current-audio causal argmax, but a 16-token matrix execution can produce slightly different logits from serial single-token execution. This is a change in the ASR final result, not just scheduling. It can change older words, numbers or negations and become eligible for normal final dispatch. None of the storage protections establishes linguistic correctness. The 440 identical-input finals, per-case regressions and real-time/native outcomes must therefore decide whether to retain it. This static review found no concrete new corruption, stale-token acceptance or ownership-bypass counterexample; it does not assert that none exists or that the linguistic gate has passed.
