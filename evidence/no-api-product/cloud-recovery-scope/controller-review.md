# 生产采集与恢复授权修复

2026-11-07。初始缺陷：首次云端连接成功后，后台恢复使用当前 factory 处理旧 failed/queued 本地原音，没有录音时授权范围。此问题会造成意外历史上传，必须在交付前关闭。

## 实现

- CaptureWorker 在创建原音之前固定设置 snapshot；授权范围写入成功后才创建云会话。设置代次改变由工厂拒绝过期任务，原音独立保存。
- 自动恢复读取录音的全部活动目的地授权，任何服务/地区/Workspace/模型/用途/凭据身份不匹配都限制为同代本机 snapshot，不推断、补授旧权限。
- 本机资源暂不可用时释放恢复领取，不消耗三次识别机会。
- 档案按钮依据已应用设置显示本机/云端；点击同步捕获所见配置，实际任务开始时若配置改变则只在本机处理。显式云端重识别只授权所选录音。
- 密钥修改前同步撤权；取凭据后再次检查 epoch，阻止读取中途撤权后把新账户凭据交给旧任务。

## 定向验证

`controller-tests.log`：6测试函数/3组通过，包含6种重启后来源（旧本地、Apple候选、有云授权、改Workspace、改GPT、换Key）、3种点击时配置、资源缺失连续4次不耗额度、实时采集授权与设置代次。传输及本地ASR为注入fixture，真实生产AudioController/工厂/Store/保存PCM和回放路径执行；不是云验收。

`credential-read-revocation-green.log`：阻塞在ASR及GPT凭据读取中途撤权，验证后续对应provider/仲裁调用为0、会话完成、原音不变。
