# Independent review: background native fixture isolation

Scope: read-only review of the new `UIReview` wrapper / private `ReviewPanel`, three native AX fixture windows, their runner assertions, and `AXCoordinatorProbe`'s deterministic post-dispatch mutation case. No window, AX probe, microphone, user target or long-running capture was started for this review. Historical unsafe diagnostic text was not opened. Execution evidence is owned by the coordinated native regression; this document is a code review, not another runtime pass.

## Findings

The UIReview closure correction is explicit: legacy `reviewWindow` now has one optional `interaction` closure, and forwards it by label to `reviewValidatedWindow`. The transcript-only validation uses the latter name with an explicit `validation:` label. This removes the ambiguous binding of an existing trailing control closure to a separate optional validation closure. Controls remain gated by `SAYTILE_UI_CONTROL_PROBE`; the wrapper does not silently execute them in render-only mode.

The private `ReviewPanel` cannot become key or main. Validation, interactions, captures and owned field-editor edits check both capability and actual key/main state. Programmatic `makeFirstResponder` and the real field editor's `insertText` / delegate path are retained; a successful model assignment is not substituted for native editing. The consumer's normal VoicePanel remains unchanged. These checks establish the intended diagnostic window isolation, not keyboard navigation of the consumer panel.

The three default AX fixture panels also cannot become key/main. They are transparent and ignore mouse events; Text/Owned now explicitly set both properties, matching the existing Web fixture. Their `sendEvent` guards count and reject keyDown, keyUp and flagsChanged without examining keyboard characters. The native text receiver additionally rejects keyDown in its default background mode. The optional foreground fixture remains separately armed and cannot enable its keyboard, visibility or mouse path before the pre-existing one-shot activation guard. No foreground run was requested here.

Isolation is a failure condition, not merely a log: initial synthetic content/caret must be correct, final key/main state must remain false and keyboard-event counts must remain zero. Owned-range replies enforce these guards on every IPC response. Thus blocking an accidental Return/key event cannot hide it behind a zero `sends` count. Unknown fixture content is represented only by a placeholder and UTF-16 length; the tests fail instead of accepting that content. Actual NSTextView/AXSelectedText setters are retained. Disabling automatic spelling, replacement, completion and smart insertion only removes uncontrolled target-side rewriting from the plain native fixture.

The original ordinary native **9 assertions** remain intact. The owned-range **9 scenarios** also remain intact, including precise UTF-16 range/value checks, growth/shrink, continuation, manual edits, selection and focus changes, alternate-target protection, refused replacement, uncertain restart, window close, no repeated repair and safety counters for whole-value/key/paste/unexpected payload. None has been downgraded to a mocked insertion success. The WKWebView probe still reports an acknowledged but unchanged write as `unverified`; successful notification/capability tests do not relabel it as a successful insertion.

The owned-range **focus-change scenario has a narrower, explicit boundary after the isolation fix**. A non-key panel is not assumed to publish a foreground AX focus-change notification. The fixture performs real `window.makeFirstResponder(alternate)` and reports the actual `window.firstResponder` and its accessibility identifier over the existing nonce/PID/command-checked IPC. The probe requires the returned responder to be `alternate`, its identifier to equal the run-specific alternate ID, and the actual owned AX element's identifier to match. Only then does it reflect that real responder in the already-injected target selector. It does not call the production coordinator's `invalidate`, invent an observer event, or change the expected `correctionPending` / zero unwanted setter result. This tests final target snapshot revalidation after an actual owned-window responder change. **It does not establish native background AX focus-notification delivery**, and must not be reported as such. The first run that exposed this narrower fixture boundary remains a failure receipt rather than being deleted or relabelled.

The new `TargetMutationAccess` forwards permission, snapshot, dispatch, verification, matching, observation and witness operations to the real `AXInputAccess`. After one real production dispatch it performs one explicitly separate AXSelectedText insertion of a synthetic space into the same owned fixture. It does not return a forged confirmation or alter production code. Its five checks require: unverified outcome and invalidated binding; exactly one production dispatch plus one separately counted target mutation with exact surrounding text; one durable unverified dispatch row and no owned range; explicit repeat refused with no extra dispatch; and no owned activation. A failure retains the isolated test database. This deterministically exercises a target change in the confirmation interval, rather than relying on unpredictable outside input or timing-only retries.

## Conclusion and limits

No definite P0/P1 issue or weakened production input protection was found in the reviewed change, including the final responder-IPC and transparent/mouse-isolation additions. All modified input harness logic is test-only; the only application-source change in this review is the diagnostic UIReview path. A minor top-of-file scope comment was sent to the owner so the newly declared mutation seam is not described as target-selection-only.

The subsequent native runs must still establish that the real AX/field-editor paths work under these stricter window constraints. They cannot by themselves prove why the earlier unexplained caret change occurred, nor retroactively establish that historical fixtures could never receive keyboard focus. Historical unknowns remain unknown; no earlier unsafe raw text is needed to demonstrate this new deterministic behavior. Production foreground resolution, arbitrary third-party targets and human keyboard use remain separate scopes.
