# 中文本地识别 · M5 产品复测

产品基线为 PR #23 的 0.12 build 373，安装源码 `a4f9f08656d1a22d2e0b6c59ad60e36452881010`。分支起点 `0e1cbc48236146c5b82e5517a59e0c18cbcb7a50` 的额外提交为内测证据。运行实例身份为 app.saytile.mac。M5，24 GiB，按设备 UID 绑定的内置麦克风为单声道 48 kHz。电平采样时系统默认输入为蓝牙，未打开该设备。个人档案仅在本机读取模型编号和状态的汇总，不纳入公共语料。

本轮使用仓库的固定 420 段中文语音与 20 个派生样本。原速窗口测量独占模型推理，使用同一组 15 段独立公开人声。比较包含模型直出、采集环/VAD/归档、已布局的原生文字、音频结束后的确认及实际资源。CER 保留原计分器。个人口音没有参考转写。

第一轮修正 WebRTC hangover 被计入新讲话起点、Apple 零时长事件的定稿时间、本地模型首字前失败的追踪。1.7B 使用同一原生 MLX 工作者试验分块增量和官方中文语言标记。接下来验证原速、完整语料与长时间稳定性，再确定自动策略。

正式安装基础是 0.12。独立候选的原速证据涵盖同一组 15 段，在 [逐条窗口记录](candidate/panels) 可区分模型发布与文字实际出现在 AppKit 上的时刻。当前 0.6B 强制中文方案在 420 段上有 967/10,663 个字符编辑错误，旧版 Apple 有 1,261 个。强制中文会翻译个别混说中的英文，因此另行验证了不强制语言的同一模型；两个配置的指标分别保存。[混说对照](language-ab/README.md)

修复了连续讲话达到 30 秒切段时，紧接暂停或 EOF 会丢失不足 60 毫秒原音的问题。10 组停止位置都从重新打开的 SQLite 找到对应 WAV，逐字节校验通过。[原音边界](boundary-integrity.md)
