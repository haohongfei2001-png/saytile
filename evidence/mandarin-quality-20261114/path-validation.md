# 本地录音、分段和中断恢复

MacBook Air M5，24 GiB。音频夹具仅包含公开许可语料与单独生成的 PCM；故障测试使用临时 SQLite。普通话原速窗口与批量识别的结果另计。

| 检查 | 实测结果 |
| --- | --- |
| 420 条不同原文的原始公开样本 | PASS，逐文件校验固定 WAV 哈希。VoiceSegmenter 在 420/420 条均建立录音。旧版建立 457 段，改后 427 段。160 条 FLEURS 从 197 段变为 167 段。其他 260 条各一段。 |
| 20 条降音量或加噪派生 | PASS，20/20 条均建立录音。28 段变为 21 段，耗时和 CER 由独立评测确定。 |
| 分类与句首不确定性 | 有 403 条在两版都只分成一段。169 条的新起音判定比旧版晚至少 100 ms，10 条晚至少 1 秒，最大 3.02 秒。这个时间标记不能直接判断是否漏字，产品还会保留约 1 秒前置 PCM。逐条收据用于与相同录音的转写对照。 |
| 三种强制退出 | PASS，三个临时进程分别在采集期间、首次检查点写入失败、原音文件切换时收到 SIGKILL。重新启动两次均能检验完整的 244,000、4,000、240,000 个 PCM 帧，分别恢复原记录和未确认文字版本。清单检查了字节、元数据、SQLite 完整性及禁止自动重投。 |
| 真实缺模型、离线路由 | PASS，缺失 Qwen 权重的真实 CaptureWorker 会话失败后仍可继续追加 PCM，保存的 960 个 PCM16 帧逐字节一致。该录音只记载 Qwen；后续段使用新选择。档案票据沿用创建时所选引擎。两种测试权重刻意留空，以检验路由与失败保全，替代引擎的真实出字由原速窗口单独检验。 |
| 内置麦克风路由与电平 | PASS，按内置输入 UID 单独绑定并核对 AudioQueue 返回的实际 UID，48 kHz、单声道，24 个系统回调、20 次有效电平读数。实测期间默认输入已切为蓝牙，未更改默认输入，也未从蓝牙采样。 |
| 内置麦克风有声识别 | BLOCKED，本次电平检查时系统报告笔记本合盖，20 次读数均在 −120 dBFS。已授权的公开音频原速输入属于另一项验收。 |
| 用户本人自然讲话、现场口音质量、物理断电 | NOT_RUN。 |

两次分段探针的产品相关源码分别为 `0e1cbc4` 和 `46c544d`。每条音频的 SHA-256、总帧数、起止帧和实际进入 journal 的采样长度保存在 [配对帧记录](segmentation-frames.jsonl)；独立读取两份探针 JSON 再次逐行比对，并重新校验了 440 个 WAV。各语料统计与源文件摘要见[分段收据](segmentation-summary.json)。

SIGKILL 与媒体重开基于 `d2da535`。[中断收据](path-interruption.json) 列出每次重开的原生断言。[设备电平收据](hardware-meter.json) 附探针及二进制 SHA。内置输入在合盖时仍可能以正常采样率返回缓冲；本轮没有把回调数计为有声输入。

复核使用现有 `scripts/test-native.sh`。49 项针对分段、定稿和已投递修订的测试通过；另一次 21 项针对启动恢复、权限状态和存储故障的测试通过。两组共享部分用例，不能相加当成独立用例数。对新路由与本地模型完整性的定向运行另有 10 项通过。对应未提交变更的测试以文件摘要绑定，[原生回归收据](path-regression.json) 记录原始测试选择和通过数。整套 CI 的最终结果见 PR。
