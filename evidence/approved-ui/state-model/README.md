# Approved single-control state model

Implemented against the current approved compact-panel document, section 4. No color sampling or original-image match is claimed: the original asset bytes remain unavailable. This change owns only `AppModel.swift` and its isolated controller probe; it does not change the capture/recognition engine, consumer Views or VoicePanel.

`panelCapturePresentation` provides `state`, `symbolName`, `accessibilityLabel`, `accessibilityValue` and `liveVoiceLevel`. Four ordinary states are `unopened` (mic), `standby` (quiet circle), `recognizing` (waveform) and `paused` (pause). `starting` and `recoveryNeeded` are explicit preparation/error exceptions, not additional normal completion states. Existing action labels remain usable by settings/menu/VoiceOver. No state label is intended as visible panel text.

Amplitude comes from the existing `AudioController.level` dependency only when VAD reports `.speaking`. Missing, nonfinite or negative measurements return nil; valid values are bounded to 0...1. Ambient levels in standby and pending ASR/fusion yield nil. Rendering must remain static in those conditions, without an oscillator or fabricated waveform.

The current utterance is tracked independently from the visible panel: one bounded latest-record query after the current user-started capture session, plus one identity/terminal latch. Open audio, queued recognition, running ASR and current fusion all remain recognizing. Completion/failure/cancellation settle quietly without stopping capture. Historical reuse, older session queues, later re-recognition of the settled record and deletion of the newest record cannot revive historical activity. Clearing the visible transcript does not hide actual pending current work.

`floatingEntryEnabled` defaults false, uses the AppModel's injected preference domain, reloads persisted choices and posts `SaytileFloatingEntryChanged` only for an actual user setting change. This preference does not start capture or create another recording control.

The focused production AppModel probe passed **97 checks**: **31 state/preference checks** plus **66 existing controller/data checks**. Store-backed cases include current open → queued → running → fusion → completed, silent return to standby, pause/resume with older work pending, explicitly reused historical fusion, clear-panel independence, settled-record retry and deletion fallback. Synthetic meter cases cover changing amplitude, ambient input, missing/NaN/infinite/negative levels and clamping. Preference tests cover default-off, persistence, reload and notification count. Real microphone amplitude and rendered visual quality are not claimed by this controller probe.

The first run exposed an invalid fixture step: deleting a still-open recording correctly raised `StoreError.recordingActive`. The test now seals that synthetic recording before deletion, matching the existing Store contract. The original failure is retained as `run-fixture-recording-active.log`; no production deletion guard was relaxed.

The probe was narrowly compiled with the actual new AppModel and a read-only existing SaytileKit static library. At the time of this state-model run, all **90** library/package source hashes matched the library's already verified 1067 source; `library-identity.json` records that comparison and library hash. A fresh probe/module cache was used, and the old source/build directories were not changed. `verification.json` binds the source and executable/log hashes. The later `DiagnosticDirectory`/ConnectionSetup repair has separate focused evidence in `../diagnostic-boundary`; it was not part of this earlier static library. Root owns the subsequent integrated package checks. No full native suite, long run, live cloud call, real audio capture, external insertion or visual acceptance was performed here.
