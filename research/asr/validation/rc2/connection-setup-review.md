# Independent connection-setup boundary review

2026-11-07. Read-only source review by the credentials/settings reviewer. Reviewed `ConnectionSetup.swift`, `ConnectionSetupView.swift`, the setup branch and termination lifecycle in `SaytileApp.swift`, `open-rc2-connection-setup.sh`, associated tests, and the called AppModel/credential/recovery methods. No visible window, microphone, actual credential read, provider request or broad test rerun was performed for this review.

## Material finding

**P2 — production subtree exclusion (fixed after review).** At initial review time `ConnectionSetupRequest.init` rejects a resolved root equal to the production `Application Support/Saytile` directory, but not an empty/new descendant of that directory. A direct CLI invocation can therefore choose a fresh `Saytile/Audio/<new-directory>` as the supposedly isolated store. It does not open the existing parent database or read existing audio, but it creates setup artifacts within the production tree and violates the intended isolation boundary. The normal helper script's `dist/connection-setup.XXXXXX` path avoids this case. Recommended fix: reject the canonical production root and every descendant before constructing Store, while retaining normal `/tmp` parent aliases. Reported to the root agent; no source edits made by this reviewer.

**Resolution rechecked:** root now rejects `canonicalRoot == production.path` and `canonicalRoot.hasPrefix(production.path + "/")` before the empty-directory checks or Store construction. The component separator avoids rejecting unrelated sibling names. Added `productionTreeIsRejectedWithoutTouchingIt` covers the production root and an Audio descendant using URL construction and rejection only; it does not create a directory or open the production database. Source and regression reviewed independently; root owns execution of the final expanded suite. No remaining finding in the reviewed normal connection-setup path.

## Confirmed boundaries

- Setup arguments are checked before Store construction. Missing absolute paths, non-empty root, output outside the root and mixed diagnostic modes are rejected. Existing leaf symlinks are rejected by StorePath; output is a JSON file directly inside the declared root.
- A fresh diagnostic UserDefaults suite starts with cloud disabled and automatic recovery false. The reused setup section disables the automatic recovery control, and export rejects recovery=true. Setup exposes no recorder, archive, status menu or capture shortcut; it returns before normal UI action registration. Controller lifecycle callbacks do not spontaneously start capture because requestedRunning is false. Applying a cloud configuration updates the factory but does not itself create a provider session.
- The isolated store is empty when admitted. Startup repair only targets this store. This window provides no audio import or retry action. No normal path from its controls to a model request was found.
- Key saving/deletion is an explicit user operation in the reused native settings. Presence checks request metadata only; neither setup validation nor export calls `CloudCredentialStore.read`. Credentials use the normal Saytile Keychain accounts so the later candidate can use them; explicitly saved keys remain even if the user closes without exporting. This is documented and is distinct from installing/replacing RC1.
- Export uses only the applied `RecognitionConfiguration`, rejects unapplied edits, requires highest quality and the five core roles/providers, validates processing consent and key presence, and writes without overwriting an existing destination. The Codable model has no secret field. Workspace, context and configuration IDs are non-secret configuration, nevertheless the docs correctly keep the output local and out of public commits. The setup store is restricted by SaytileStore and the resulting JSON is set to mode0600.
- Finish, Close and the window close button route through NSApplication termination. AppModel shuts down audio and closes Store; the temporary preferences suite is removed on normal termination. The window has no transcript editor, so it cannot produce an unsaved transcript draft that would reopen the normal panel. Forced process termination is not claimed to clear temporary preferences.
- The launcher creates a new temporary directory under this checkout's ignored dist directory and invokes the candidate executable directly; it does not install, launch the installed RC1 or modify security permissions. Candidate absolute-path containment, RC2 version and clean-source metadata are checked. These checks do not independently prove a provider connection or replace final package/signature verification.
